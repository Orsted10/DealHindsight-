## 1. Project Summary

**DealHindsight** is a sales-negotiation intelligence co-pilot that uses [Hindsight](https://github.com/vectorize-io/hindsight) agent memory to remember every objection, competitor mention, and stakeholder concern across multi-week B2B sales cycles.

### What it does
- **Side-by-side coach comparison:** Chat with two AI sales coaches simultaneously — one stateless (forgets everything between calls), one with Hindsight memory (removes every objection and adapts its strategy).
- **Call log ingestion:** Simulated or manual call transcripts are parsed for objections, competitors, and pricing data, then stored via Hindsight's `retain` API.
- **Memory recall:** When a rep asks a question, Hindsight's `recall` API surfaces relevant past calls so the coach recommends tactics based on what worked before.
- **Strategic reflection:** The `reflect` API synthesizes high-level sales beliefs from accumulated call data.
- **Dual mode:** Runs fully offline with a local mock engine (zero dependencies) or live with Hindsight Cloud + OpenAI/Groq.

### Tech stack

|---|---|
| Backend | Python, FastAPI, Pydantic |
| Frontend | React 19, Vite, TypeScript |
| Memory | Hindsight SDK (or local JSON mock) |
| LLM | OpenAI / Groq (or simulated fallback) |
| Design | Dark glassmorphism, custom CSS |

## 3. Step 2: Full Article Draft

# I Built a Sales Coach That Remembers Every Objection

Enterprise B2B sales cycles stretch for weeks. Multiple calls, changing stakeholders, shifting objections. By the time you're in call four, you've forgotten what Jane said in call two — and your AI assistant forgot it even faster.

I got tired of stateless chatbots giving the same generic advice meeting after meeting. So I built DealHindsight: a sales co-pilot that uses Hindsight's persistent memory layer to actually remember what happened in previous calls. The result is a side-by-side comparison that makes the difference between "with memory" and "without memory" painfully visible.

## What I built

DealHindsight is a two-panel sales workspace. On the left, a vanilla AI sales coach that starts fresh every conversation. On the right, an identical coach backed by Hindsight's agent memory. Both answer the same question at the same time.

The difference is stark. Ask the vanilla coach "How should I handle pricing objections?" and it says "Ask about their budget and offer standard pricing guides." Ask the memory-backed coach after a single logged call, and it says "Jane Doe raised SOC-2 compliance as a legal blocker last time. Competitor X quoted $80k. Pitch our AWS dedicated VPC setup at $79k to bypass the security audit and beat their pricing."

That shift from generic to specific is exactly what I wanted to build.

## How it works

The system has three layers:

### 1. Call ingestion and memory storage

When a sales call happens — whether simulated or manually logged — the transcript gets parsed for objections, competitor mentions, and pricing data. That structured data gets stored in Hindsight using the `retain` API:

```python
hindsight_wrapper.retain(
    bank_id=BANK_ID,
    content=memory_content,
    tags=[comp_tag, "call-log", "objection"],
    metadata={"deal_id": payload.deal_id, "type": "experience"},
    context=f"Sales transcript log for {payload.deal_id}"
)
```

The tags are critical. Each memory gets tagged with the company name and content type. When a rep later asks a question about "Acme Corp," the recall query filters by the `acme-corp` tag, returning only relevant history.

### 2. Context-aware recall

When the rep sends a chat message, the backend fires two parallel requests to Hindsight's `recall` API — one filtered by company tag, one unfiltered:

```python
recall_res = hindsight_wrapper.recall(
    bank_id=BANK_ID,
    query=payload.message,
    tags=[comp_tag],
    limit=5
)
```

The recalled memories get injected into the system prompt for one coach, while the other coach gets a prompt that explicitly states it has no historical context. Both then call the same LLM backend.

### 3. Strategic reflection

After several calls are logged, a reflection cycle runs across the memory bank. This uses Hindsight's `reflect` API to synthesize high-level beliefs from individual experiences:

```python
hindsight_wrapper.reflect(
    bank_id=BANK_ID,
    query="Identify recurring sales objections and objection-handling tactics that succeeded.",
    tags=["acme-corp", "globex", "objection"]
)
```

This is where the system graduates from remembering individual facts to forming strategic rules — like "Enterprise buyers object to multi-tenant security profiles; native VPC pitches win."

## The architecture

The stack is straightforward:

```
React frontend ↔ FastAPI backend ↔ Hindsight SDK (or local JSON mock)
                         ↕
                    OpenAI / Groq LLM
```

The Hindsight wrapper has two modes. In **simulation mode** (default), it uses a local JSON file as the memory store. No API keys needed, no dependencies. In **live mode**, it connects to Hindsight Cloud or a local Docker instance.

This dual-mode approach meant I could develop and test the full memory pipeline offline, then flip a switch for production. The LLM responses follow the same pattern — simulated text when offline, real OpenAI/Groq calls when live.

## The before/after moment that sold me

Here's the concrete scenario I built for the demo:

**Before any calls are logged:**
- Question: "How should I pitch Acme on pricing and competitors?"
- Vanilla coach: "Ask about their budget process. Offer standard pricing tiers. Send a case study."
- Hindsight coach: Same generic answer. (No memory yet — both are equally useless.)

**After logging one call where Jane Doe raises SOC-2 compliance as a blocker and mentions Competitor X's $80k quote:**
- Question: "How should I pitch Acme on pricing and competitors?"
- Vanilla coach: Same generic answer. Still useless.
- Hindsight coach: "VP Jane Doe blocked on SOC-2. Competitor X at $80k. Pitch AWS VPC isolation at $79k."

This single interaction made the entire project worth building. The vanilla coach is frozen in time. The Hindsight coach adapts after one data point.

## What surprised me

Three things caught me off guard:

1. **The mock layer was more useful than expected.** I built the local JSON mock as a development shortcut, but it became the primary demo driver. The full pipeline works identically with or without a live Hindsight instance. This made testing and iteration dramatically faster.

2. **Tag-based filtering matters more than query quality.** Early versions tried to rely purely on semantic search. Switching to company-specific tags (`acme-corp`, `globex`) made recall far more relevant. The tag is the primary filter; the query is secondary.

3. **The "no memory" coach is still useful.** I initially built the side-by-side view as a debugging tool. But watching both responses together makes the value of memory tangible in a way that a single coach never could. The contrast is the feature.

## Lessons learned

1. **Agent memory isn't just about storing data — it's about retrieving the right data at the right time.** The `recall` API is where the magic happens, not `retain`. Spend more time on your retrieval strategy than your storage strategy.

2. **A mock layer is not a shortcut — it's a superpower.** Being able to run the entire system offline means you can develop, demo, and debug without network dependencies. The live mode becomes a deployment concern, not a development blocker.

3. **Side-by-side comparison beats any benchmark.** Instead of trying to measure "how much better" the memory-augmented agent is, show both agents answering the same question. Engineers trust their eyes more than metrics.

4. **Tags are your indexing strategy.** If you dump everything into one memory bank with no structure, retrieval suffers. Invest time in a tagging taxonomy that maps to your domain.

5. **Reflection turns data into strategy.** Individual call logs are useful. But running a reflection cycle across accumulated memories is where the system develops actual judgment. Make reflection a regular part of your pipeline, not an afterthought.

## What's next

The current system works with mock data and simulated LLM responses. The next step is wiring it to real call transcripts from Gong or Chorus, connecting live LLM APIs, and running it against actual deal pipelines. The architecture is ready — it just needs real data.

I've open-sourced the codebase. If you're building an agent that needs to remember what happened last time, I hope this gives you a practical reference for what a memory-augmented system looks like in practice.
